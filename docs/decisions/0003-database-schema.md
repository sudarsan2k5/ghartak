# 0003 — Production database schema

Status: accepted. The multi-store catalogue, store-manager role, and one-active-cart-per-store rules are superseded by [0004](0004-central-inventory.md).

## Context

The marketplace needs a durable schema before product, cart, checkout, or payment APIs exist. PostgreSQL 17 on the existing Docker volume is the source of truth. Drizzle owns the schema and SQL migrations.

## Decisions

- Primary keys are UUIDs generated by PostgreSQL. Money is stored as integer paise, with checks that order totals and line totals match their parts. Currency is constrained to INR.
- A product belongs to the shared catalog. `store_products` originally held a price and stock quantity per store. [0004](0004-central-inventory.md) keeps those columns and limits each product to one listing. A cart item must still reference that listing through the composite foreign key.
- Order items and order addresses copy the product and delivery details needed to fulfill the order. Later edits to the catalog or the customer's address book do not change those snapshots. `source_address_id` is set to null if the saved address is removed. Guest COD orders ([0007](0007-guest-cod-checkout.md)) may omit `orders.user_id` and structured address fields; the free-text delivery line is stored on `order_addresses.line1`.
- Orders, order items, order addresses, status events, payments, and inventory movements use `ON DELETE RESTRICT`. Cart items are deleted with their cart. Saved addresses and role rows are deleted with the user. Payment rows store a provider, provider ids, status, amount, and an idempotency key. They do not store card numbers or credentials.
- Order status transitions are validated by `assertOrderStatusTransition` in the database package. The database stores every status change, and the future order service must call that check inside the same transaction as the status update.
- Inventory history is append-only. Opening stock is an addition movement. Stock quantity changes belong in the same transaction as the movement that explains them.
- A customer may have many addresses, with at most one default. The original schema allowed one active cart per store. [0004](0004-central-inventory.md) changes that to one active cart per customer.
- The original schema gave store managers a store. [0004](0004-central-inventory.md) removes that role. Customer, admin, and delivery-partner roles remain.
- The local development database remains the PostgreSQL 17 container on `127.0.0.1:5433`. Migrations do not recreate Docker volumes.
- PostgreSQL enum lists live beside the Drizzle tables. Zod enums in `@ghartak/contracts` mirror them, and `pnpm db:verify` fails if the two lists diverge. Drizzle Kit loads the schema through CommonJS, which cannot import the ESM contracts package.

## Consequences

Generate SQL with `pnpm db:generate`, review it, then apply it with `pnpm db:migrate`. `pnpm db:seed` inserts the demo village data and does nothing on conflict. `pnpm db:verify` checks constraints against that database.
